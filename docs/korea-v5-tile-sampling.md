# 대한민국 좌표 선택배수 3 (v6; v5 비트맵 재사용)

2026-10-30. 기준 GitHub `main` 커밋 `676e00f453487b83cf6d7ec879ed3b5071ac8f6a`의 v5 선택배수 2를 v6 선택배수 3으로 변경한다. 문서 경로와 비트맵 파일 이름은 v5를 유지하며, 비트맵 자체는 재사용한다. 기존 v4의 폴리곤 13,701개, 모든 섬·구멍·원본 정점과 97개 경계 바이너리는 동일하다.

기존 2^32×2^32개의 GRS80 등면적 격자점 중 선택 타일에 속하는 점에 세 번씩 동일한 확률로 선택 기회를 배정한다. 입력 `u64` 상위 18비트 `selector`가 `237339` 이상이면 즉시 거부한다. 그 아래이면 `floor(selector / 3)`번째 오름차순 타일을 선택한다. 타일 순번이 `r`이면 선택값 `3r`, `3r+1`, `3r+2`가 해당 타일에 대응한다. 타일 위치는 512×512 전체 등면적 격자에서 세로 상위 9비트·가로 상위 9비트이며, 나머지 46비트의 상위 23비트는 세로 인덱스 하위, 하위 23비트는 가로 인덱스 하위에 합친다. 결과인 원래 축당 32비트 인덱스는 변경 없는 `candidate` 함수와 원본 경계 `covers` 판정에 넣는다. `num_64`와 이후 전체 64비트 보완 난수는 매번 동일한 입력으로 기본 필드·럭키스타·한글·NMS·대한민국 좌표의 미완성 상태에 전달한다. 좌표는 다른 필드와 동일한 공통 완료 조건의 구성원이며, 마지막 단독 난수 요청 루프는 없다. 각 필드는 수락한 값을 고정하고, 그 뒤의 입력은 건너뛴다. 세계 좌표와 NMS의 포탈/은하 좌표는 최초 `num_64`만으로 확정한다. 전체 후보들은 독립 균등한 64비트 공급열의 동일한 순서를 사용하며 좌표용으로 자른 비트나 별도 PRNG는 사용하지 않는다. 공급 실패, 누락·손상, 취소, 1,024개 보완 한도는 기존 오류 방식대로 처리한다.

`tile-select-v5.bin`은 512×512개 타일에 대한 32,768바이트 비트맵이다. 각 바이트의 비트 번호는 타일 번호의 하위 세 비트다. 낮은 타일 번호부터 0/1을 읽어 1인 번호를 오름차순으로 펼치면 79,113개가 된다. SHA-256은 `492fdbeee7e7a64816d7ea90c57cb5773685fbf96e0b95911a8b7cdcfbf2ae8b`이며, 원본 v4 루트 SHA-256은 `8cb20a5c0da9c3d6225efb0323e24a4f992eb3029a772da3a71a55d3f503bf17`이다. 생성 규칙은 기존 1/32° 지리타일의 `INSIDE`·`MIXED`를 1e-6° 보수적 확장해 512×512 등면적 타일과 교차시키는 것이다. `OUTSIDE`를 국토라고 가정하지 않으며 혼합 셀의 실제 최종 판정은 기존 판정기에 맡긴다. 원래 축당 32비트 격자와 모든 작은 섬의 도달성을 유지한다.

정확한 수락 격자점 수를 `M`, 전체 입력 수를 `C=2^64`라고 하면 매 입력의 수락률은 v5의 `2M/C`에서 v6의 `3M/C`로 증가한다. 동일한 경계와 균등·독립 입력을 전제로 각 성공 격자점의 조건부 선택 확률은 같으며, 1,024개 보완 한도도 유지한다. 원본 면적비 `0.2519893267571422`를 이용한 근삿값은 최초 수락률 약 75.597%, 후속 좌표 후보 필요 확률 약 24.403%, 좌표 보완 후보 평균 약 0.323개다. 면적비는 실제 대한민국의 모든 유한 격자점을 전수 계수한 값이 아니다. 공통 공급열의 전체 보완 소비량은 다른 필드의 완료 조건에도 의존하므로 이 좌표 전용 지표와 구분한다.

v5 선택배수 2의 도입 전 실험 기록: 기준 Node v22.16.0의 당시 배포 웹 판정기, 고정 10,000건×5회는 배수 2의 중앙값 5.920초, 기존 6.460초로 8.36% 감소, 실제 `supp` 평균 0.98914 대 2.95564였다. 이는 채택 전 별도 로컬 파일 백엔드·난수 비용 제외 실측이며, 최종 변경 코드의 Rust/브라우저 성능·네트워크 포함 수치라고 표시하지 않는다. 인덱스 데이터 구조와 다운로드 비용은 원본 실험의 316,452바이트 원시 목록에서 현재 32,768바이트 비트맵으로 감소했다.

v6의 고정 `num_64 -> 좌표` 대응은 v5와 달라진다. 같은 입력열에서도 대한민국 좌표와 전체 보완 소비량이 바뀔 수 있으며, 공급열을 연속 사용하면 후속 레코드의 시작 위치에도 영향을 준다. v5와 좌표가 계속 일치하거나 개별 입력의 보완 소비량이 반드시 줄어든다고 주장하지 않는다. 배수 3의 균등성은 각 타일에 세 개의 18비트 슬롯이 있고 각 슬롯에 정확히 2^46개 내부 인덱스가 일대일 대응하는 것에서 따라온다. 따라서 기존 유효 격자점마다 원본 `u64` 세 개가 대응한다. 모든 유효 격자 셀을 포함한 보수적 타일 목록이 완전하다는 것은 원본 상태 분류·수치 경계 안전 여유를 전제로 추가 검증한다.

v5 선택배수 2의 공통 완료 루프 검증 기록: 단계별 보조난수 재사용을 사용한 이전 PR #31 버전의 결정적 Rust 10,000건에서는 14,354개, 완전 통합 구현의 같은 입력 코퍼스에 대한 실제 경계 기반 Rust 릴리스·JavaScript 10,000건에서는 모두 14,355개를 읽었다. 전자는 이전 버전의 검증 자료이며, 후자의 실험은 결정적 입력을 사용하므로 하드웨어 난수 공급과 파일 저장을 포함하는 실제 실행시간을 대신하지 않는다. 통합 후보의 세계 좌표·고정 포탈/은하 좌표는 기존과 일치하며 럭키스타·한글·NMS 가변 번호는 난수 순서를 바꾼 결과로 달라질 수 있다. 한글은 각 음절의 16비트값이 55,859 이하일 때 11,172로 나눈 나머지를 수락해 편향을 방지한다. NMS는 행성 0~11의 4비트 입력, 태양계 0~3,834의 12비트 입력을 각각 거부표본으로 수락한다.
