# 대한민국 좌표 v4: JavaScript 4.65% 개선 후보 채택

2026-10-29, 사용자가 기존 데이터 배치를 유지한 JavaScript 후보의 채택을 요청하여 최종 구성을 갱신했다. **Rust 압축 해제·SHA-256 최적화에 JavaScript의 짧은 Huffman 코드 조회 최적화를 추가 채택한다.** 64 KiB 데이터 재배치는 계속 제외한다.

이전 [성능 보고서](korea-v4-performance-20261029.md)와 그 JSON, 원시 표본 및 전달한 ZIP은 당시 판정의 체크포인트로 보존했다. 최신 최종판의 근거는 이 문서와 [통합 JSON](korea-v4-performance-accepted-js-20261029.json)이다. 원래 Git 기준은 `c2da4b054e9045c96d0d335c7f8ea20b0edcaa63`이고, 웹 비교의 직접 기준은 첫 v4 JS `94f8206937d10cc03e992dd15b174ad20cf3707c979a8d482fe9e80bb9659785`다. 원래 v3와 직전 v4를 혼용하지 않는다.

## 1. 채택 판단을 바꾼 이유

앞서 사용한 5%는 지시서나 사용자가 요구한 최소 개선율이 아니라, 작업 중 정한 내부 선별 기준이었다. 후보는 실제로 4.647% 빨랐으나 그 수치 문턱만으로 제외했다. 사용자의 “이것도 채택 채택해야 하는 거 아닌가요?”라는 지적에 따라 이 후보의 이득, 추가 비용, 동치 및 자원 경계를 함께 평가해 채택으로 바꿨다.

기존의 5% 문턱을 넘었다고 재표기하지 않는다. 측정값·표본 수·이전 판정은 그대로다. 이번 결정은 이 작은 변경에 대한 사용자 요청을 반영한 재평가이며, 다른 검사의 기준을 낮추거나 영구 CI 정책을 바꾸는 결정이 아니다. 통계적 유의성이나 모든 브라우저·네트워크 환경에서 같은 개선율을 보장한다고 주장하지 않는다.

판정 근거는 다음과 같다.

- 같은 입력의 5개 쌍 모두 후보가 빨랐다.
- 이번 표본에서는 후보 전체 실행시간 범위와 기준 범위가 겹치지 않았다.
- 추가 비용은 JavaScript 코드 2줄·123바이트다. 새 캐시·테이블·수신 계층·의존성을 추가하지 않는다.
- 실제 HTTP 요청 수, 캐시 점유, fetch·hash 호출 수와 보완 입력 소비가 같다.
- 검증한 좌표 binary64 비트와 보완 소비량은 모두 일치한다.

## 2. 실제 코드 변경과 보호한 계약

`inflateSymbol`에서 9비트 lookup을 하기 위한 범용 `bits.peek(9)` 호출을 두 바이트 결합·시프트·마스크 연산으로 바꿨다. `bits.position + 9 <= bits.length` 검사는 그대로이며, 이를 통과하면 필요한 두 바이트가 존재한다. 바이트 내 시작 위치는 0–7비트이므로 두 바이트는 필요한 최대 16비트를 모두 담는다. 같은 9비트를 같은 기존 lookup table에 전달한다. 제품의 압축 페이지는 최대 512 KiB 조각 안에 있으므로 비트 위치도 32비트 시프트가 정확히 표현하는 범위 안이다.

새 lookup table을 만들지 않았고 긴 코드·입력 끝 구간의 fallback, Adler-32, 출력 길이 상한, 불완전 트리와 잘못된 코드의 오류 판정도 그대로다. GRS80 수학·52회 이분법·32+32비트 후보·독립 전체 supp64의 순서·1,024회 한도·경계 폴리곤은 바꾸지 않는다. 검증용 export나 성능 계측 코드는 제품에 넣지 않는다.

최종 JavaScript는 측정·독립 검증을 완료한 후보와 정확히 같은 바이트다.

```text
befe878c22c1ec2307ff36ed4f48c3a1aba8f40bf0c5bc8750bdd114077bb71c
```

HTML은 개선한 모듈을 불러오도록 `?v=4`를 `?v=4.1`로 바꿨다. 최종 포맷터 출력에서 이 쿼리 문자열 외의 내용 차이는 없다. 최종 HTML SHA-256은 다음과 같다.

```text
1c70e62ab52bae840b540f7ee9e9a6b6af5b54ac4f6e68d1ad56b1576134e83d
```

## 4. 유지한 데이터·메모리·Rust 결과

경계 데이터는 96개 조각과 루트를 합친 97개 바이너리·50,276,630바이트 그대로다. 데이터·manifest·기하 검증 파일은 첫 v4와 같다. 최종 루트 SHA는 `8cb20a5c0da9c3d6225efb0323e24a4f992eb3029a772da3a71a55d3f503bf17`이다. 조각 상한은 512 KiB이며 64 KiB 후보의 파일이나 생성 정책은 제품에 포함하지 않는다.

웹 압축 캐시는 8개·4 MiB, 해제 캐시는 4,096개·4 MiB, 진행 중 예약과 상한도 같다. 5개 쌍의 실제 캐시 회계가 일치한다. 이번 코드에는 새 캐시나 유지되는 객체가 없지만, 전체 JS heap·브라우저 RSS가 바이트까지 같다고 추정하지 않는다. 이 상한은 브라우저 자체 HTTP 캐시·모든 임시 버퍼·전체 프로세스 메모리의 상한이 아니다.

Rust 소스·Cargo 입력·경계 데이터가 직전 최적화판과 동일하므로 그 최종 release·정적 검사·패키징·성능 증거를 재사용한다. 실제 재빌드하거나 다시 측정한 것으로 기록하지 않는다. 사용한 컴파일러는 같은 최적화 주기에 고정한 Rust 1.99.1이며 PGO는 사용하지 않는다.

| --- | ---: | ---: |

현재 ELF SHA-256은 `3d12310ba41743e7a667021beeec861004ff73fe3a64aa2e30935573f527b50e`다. 이 값은 이전 최종 ELF와 같다.

## 5. 최종 검증과 Nu 예외

기존 전체 압축 해제 독립 검증은 같은 후보의 코드임을 연결해 재사용한다. 25,348개 압축 페이지·84,560,888바이트가 Python zlib와 같았고, 정상 fixture 10개 및 손상·잘린 입력 등 1,506개 오류 검사가 통과했다. 추출한 decoder 검증 모듈의 해시와 제품 모듈의 해시는 서로 다르므로, 추출 코드의 정확한 관계를 증거에 기록한다. Node의 10,650개 독립 공간 점과 18개 계약·손상·네트워크 오류 검사도 제품 SHA가 같은 후보의 결과를 재사용한다.

최종 제품 모듈에 계측이나 export를 추가하지 않은 상태로 Chromium 151.0.7922.34, Firefox 153.0, WebKit 26.5에서 고정 10,000건씩 기능 검증을 새로 수행했다. 각 엔진은 29,278개의 보완 입력을 읽었고, 좌표 비트·소비 불일치 0건, pageerror 0건, crash·watchdog 종료 0건이었다. 이는 세 엔진의 기능 확인이며 기존 5회 성능 표본에 합산하지 않는다.

같은 최종 실제 HTML·JS·데이터로 수동 supp 성공, 수동 취소, crypto 실패, 실제 자동 supp 성공, geometry 요청 대기 중 clear, 캐시된 거부 반복 중 clear의 6개 시나리오를 엔진마다 확인했다. 총 18개가 통과했고, 각 페이지는 탐색 전부터 pageerror를 감시했다. 수동 성공 후 실제 TXT 다운로드는 세 엔진 모두 733바이트·같은 SHA였으며 화면 결과와 일치했고 완료 후 경계 요청은 없었다.

별도의 TXT 검사는 경계 모듈·데이터 요청을 차단한 상태에서 각 엔진이 기존 TXT의 좌표 2개를 추출하고, 잘못된 좌표를 담은 후속 TXT를 거부하면서 기존 2개 결과를 유지함을 확인했다. 경계 요청과 pageerror는 모두 0건이었다. localhost에서 제공한 실제 HTML에 로컬 TXT를 선택한 검사이며 `file://`로 HTML을 열었음을 뜻하지 않는다. 전체 성분 도달성이나 원본 기하 재생성은 반복하지 않았다.

최종 HTML은 실제 VS Code 1.144.0 내장 포맷터를 적용한 뒤 HTMLValidate 11.17.0과 Nu 26.10.12를 다시 실행했다. HTMLValidate는 종료 코드 0·진단 0이다. Nu는 기존과 정확히 같은 CSS 오류 9개·경고 0개·새 진단 0개로 종료 코드 1이다. 이전 사용자의 예외 승인을 그대로 적용하여 인수 상태만 `accepted_user_exception`으로 기록한다. 새 오류·다른 검증의 면제·CSS 삭제·검사 규칙 변경은 없다.

예외는 `field-sizing` 1개, `anchor-name` 2개, `@position-try` 1개, `position-try-fallbacks` 1개, `position-anchor` 2개, `position-area` 2개다. 이번 JS 채택 판단과 Nu의 예외는 서로 다른 결정이다.

고정 18개 도구·플랫폼 게이트의 상태는 **통과 11개, 승인된 Nu 예외 1개, 미실행 6개**다. 네 타깃 Clippy·Rust format·Linux native build/tests는 같은 Rust 소스·빌드 입력에 연결된 기존 증거를 유지하며, 세 브라우저·HTML 검사는 이번 최종 JS/HTML의 증거를 사용한다. Clippy의 기존 경고를 경고 0으로 표시하지 않는다. Windows MSVC·Intel macOS·Apple Silicon macOS 각각의 native build/tests 6개는 여전히 미실행이고, Nu 예외나 JS 채택이 이를 면제하지 않는다.
