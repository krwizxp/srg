# SRG

SRG는 하드웨어 난수를 활용해 다양한 데이터를 생성하고, 서버 시간을 기준으로 지정 시각의 작업을 실행하는 명령행 도구입니다.

## 주요 기능

- 64비트 하드웨어 난수 생성
- 숫자 비밀번호와 8자리 비밀번호 생성
- 로또, 일본 로또7, 유로밀리언 번호 생성
- 한글 음절, 국내·전세계 좌표, NMS 포탈 주소와 글리프 생성
- 다중 스레드 대량 생성, 진행률 표시와 Enter 입력 중단
- 사다리타기
- 범위 지정 무작위 정수와 실수 생성
- HTTP Date 기반 서버 시간 확인과 RTT 보정
- 목표 시각의 좌클릭 또는 F5 실행
- 난수값 수동 변환과 결과 확인

## 지원 환경

- Rust 1.99.0 이상 (소스 빌드 및 개발)
- Windows 10 22H2 이상 또는 Windows 11
- Linux 및 macOS
- Linux/macOS의 libcurl 7.85.0 이상

x86_64 환경에서는 RDSEED와 RDRAND를 활용한 생성 기능을 제공합니다. RDSEED 준비 상태를 최대 5분간 확인한 뒤 RDRAND로 이어서 실행합니다. Apple Silicon 등 다른 아키텍처에서는 서버 시간 확인과 수동 변환 기능을 중심으로 사용할 수 있습니다.

선택한 난수원과 이유를 표준 오류에 표시합니다. CLI와 메뉴는 생성 개수 64 bytes, 정수·실수·호스트 입력 4096 bytes, 사다리 입력 65536 bytes의 동일한 한도를 사용합니다. 메뉴의 줄바꿈 문자는 한도에 포함하지 않으며, 값 내부의 줄바꿈은 허용하지 않습니다.

## 빌드와 실행

```bash
rustup update stable
cargo +stable build --release --frozen
# Linux / macOS
./target/release/srg
# Windows PowerShell: .\target\release\srg.exe
```

프로그램을 실행하면 현재 환경에서 사용할 수 있는 기능을 메뉴로 안내합니다.

### 명령행 실행

```text
srg generate <count>
srg ladder <players-csv> <results-csv>
srg random-integer <min> <max>
srg random-float <min> <max>
srg time-observe <host> <seconds>
```

- `generate`: 지정한 개수의 데이터를 생성
- `ladder`: 참가자와 결과를 쉼표로 구분하여 사다리타기 실행
- `random-integer`: 지정 범위의 정수 생성
- `random-float`: 지정 범위의 실수 생성
- `time-observe`: 지정한 서버 시간을 일정 시간 관찰

생성 결과는 기본적으로 `random_data.txt`에 저장됩니다.

## 서버 시간 기능

서버 응답의 Date 헤더와 통신 시간을 바탕으로 현재 시각을 계산합니다. 호스트만 입력하면 HTTPS를 사용하며, `http://`를 지정하면 HTTP로 연결합니다.

로컬 메뉴에서는 목표 시각과 좌클릭 또는 F5 동작을 설정할 수 있습니다. Linux Wayland에서는 데스크톱 포털의 입력 권한을 사용하고, macOS에서는 시스템 설정의 손쉬운 사용 권한을 사용합니다.

## revgeo.html

`revgeo.html`은 SRG에서 생성한 좌표를 브라우저에서 확인하고 정리하는 HTML 도구입니다. 기존 파일의 좌표 추출·주소 조회는 경계 데이터 없이도 동작합니다. 난수의 국내 좌표 변환에는 `korea_boundary.js`와 `data/korea-boundary-v4/`를 같은 경로 구조로 함께 배포해야 합니다. 최신 정식 Chrome, Edge, Firefox, Safari를 지원 기준으로 사용합니다.

브라우저와 홈 화면 아이콘은 `icon.svg` 한 파일을 사용합니다. iOS/iPadOS에서는 SVG 아이콘을 지원하는 Safari 26 이상을 기준으로 합니다.

### 주요 기능

- `random_data.txt`에서 좌표 추출
- OSM Nominatim을 이용한 주소 조회
- 조회 시작, 일시정지, 재개와 중지
- 지역과 주소 기준 결과 필터링
- CSV 내보내기와 지도 열기
- `num_64`와 `supp` 수동 변환
- 기본·보조 64비트 난수 생성, 부족한 보조 난수 자동 생성 선택
- 결과 파일 저장과 클립보드 복사

### 브라우저에서 난수 생성

`난수 직접 입력` 탭에서 생성 개수(1~10,000)를 정하고 `기본 난수 생성` 또는 `보조 난수 생성`을 누르면 기존 입력 뒤에 값이 추가됩니다. 기본 난수를 생성하면 `보조 난수 자동 생성`이 켜집니다. 직접 입력만 하는 경우에는 기존처럼 보조 난수를 수동으로 입력할 수 있고, 보조 입력 대화상자에서도 난수를 생성할 수 있습니다.

웹 난수 생성은 브라우저의 `crypto.getRandomValues()`만 사용하며 Rust 실행 파일이나 WASM을 호출하지 않습니다. x86_64와 ARM 모두 같은 경로를 사용합니다. 저장소의 Rust CLI는 별도 프로그램입니다.

암호화 난수 API가 없거나 생성에 실패하면 오류를 표시합니다. 서버 난수원이나 `Math.random()`으로 대체하지 않습니다. 한 번에 최대 10,000개를 생성하고 각 64비트 값을 `BigInt`와 10진수 문자열로 유지해 정밀도를 보존합니다.

### 이용 순서

1. `revgeo.html`을 HTTP(S) 환경에서 엽니다.
2. `random_data.txt`를 끌어 놓거나 파일 선택으로 불러옵니다.
3. `좌표 추출`을 선택합니다.
4. `조회 시작`을 선택해 주소를 확인합니다.
5. 필요한 결과를 필터링하거나 CSV로 저장합니다.

주소 조회는 Nominatim 이용 정책에 맞춰 순차적으로 진행됩니다. 클립보드 기능은 HTTPS 또는 localhost와 같은 브라우저 보안 컨텍스트에서 사용할 수 있습니다.


## 대한민국 좌표 경계

국내 좌표는 SGIS 2025년 6월 30일 행정경계에 한국환경연구원 공개 군사분계선·DMZ 경계를 반영한 영역에서 추출합니다. 남측 내륙 누락 약 38.06km²를 복원하고 북측 참고 영역 약 42.27km²를 제외한 보정본을 사용합니다. 동해안의 기존 해안선 밖 약 0.371km²는 판정 미확정 영역으로 추가하지 않았습니다. 현행 작전 경계나 민간인 출입 가능 구역을 인증하는 데이터는 아닙니다. 원본 SGIS의 내륙 하천·호수 포함 정책도 유지합니다.

13,701개 폴리곤 성분, 13,713개 링과 닫힘을 포함한 원본 정점 5,205,473개를 보존합니다. 독도·마라도·서북도서를 포함하며, 폴리곤 성분 수를 섬 개수로 해석하면 안 됩니다. 자료 출처는 [SGIS](https://www.data.go.kr/data/15129688/fileData.do), [한국환경연구원 군사분계선](https://data.neins.go.kr/detail/dts-eh03eVuTQu), [DMZ](https://data.neins.go.kr/detail/dts-FeJLArLgg1)입니다. KEI 메타데이터의 작성연도는 2024이며 측량 기준일은 확인되지 않았습니다. 데이터의 원제공기관과 이용조건은 프로그램의 MIT 라이선스와 구분합니다.

### v4 등면적 거부 샘플링

첫 후보의 64비트 중 상위 18비트는 대한민국과 교차할 수 있는 512×512 등면적 타일 목록의 선택값입니다. 각 타일은 정확히 두 번 나타납니다. 나머지 46비트는 타일 내부에서 위도·경도 축에 각각 23비트씩 사용합니다. 각 축에 타일 위치 9비트를 결합해 원래의 32+32비트 등면적 격자 셀 중심을 그대로 복원합니다. 타일 선택값이 허용 범위 밖이거나 폴리곤에 포함되지 않으면 전체 64비트 `supp`를 새로 읽습니다. 위도는 기존 GRS80 누적 함수 `Q(φ)`의 단조 역산으로 구합니다. 실제 마스크의 범위는 서경계 `124.60971767856728°`, 남경계 `33.11235575873201°`, 동경계 `131.87278314710602°`, 북경계 `38.61370930167485°`입니다. 범위를 반올림하거나 확장하지 않았습니다.

후보가 원본 위경도 폴리곤의 `covers` 판정을 통과하면 그대로 반환합니다. 바깥이면 기존 공급자에서 새로운 전체 64비트 `supp`를 한 개 받아 두 축을 모두 다시 계산합니다. 다른 필드가 쓰고 남긴 비트는 재활용하지 않습니다. 외곽과 구멍의 경계는 포함하고 구멍 내부는 제외합니다. 좌표 이동·경계 단순화·대체 정점·내부 PRNG는 사용하지 않습니다.

대한민국 좌표용 보완 난수는 최초 후보가 유효하면 0회이며, 거부 1회당 한 개씩 최대 1,024개를 읽습니다. 1,024번째 보완 후보까지 수락할 수 있고, 그것도 바깥이면 오류로 종료합니다. 공급자 실패·수동 대화상자 취소·데이터 오류도 실패로 전파합니다. 기존 전체 사각형 수락률은 약 25.199%였으며, 2배수 타일 선택에서는 이론적으로 약 50.398%, 평균 보완 읽기는 약 0.984회입니다. 이전 수락률과 새로운 결과를 혼용하지 않습니다. 수동 입력에는 원하는 후보를 통과시킬 충분한 `supp`를 제공하거나 `보조 난수 자동 생성`을 사용할 수 있습니다.

균등성의 대상은 `2^32 × 2^32`개 등면적 셀 중심 중 마스크에 포함되는 유한 격자점입니다. 초기 입력과 각 보완 입력이 서로 독립인 균등 `u64`라는 전제에서, 성공을 조건으로 모든 수락 격자점의 선택 확률이 같습니다. 유한 격자·binary64 근사이므로 완전한 연속 균등분포를 뜻하지 않으며, 임의로 정한 수동 입력열에 통계적 보장을 주장하지 않습니다. Rust와 JavaScript는 같은 연산 순서, 다항식과 52회 이분법을 사용합니다. 수학적 오차 검증과 최초 언어 간 비트 일치 검증은 [v4 도입 검증 보고서](docs/korea-v4-validation-20261029.md), 후속 최적화와 동일성 재확인은 [추가 좌표 생성 성능 보고서](docs/korea-v4-coordinate-performance-20261029.md)에 기록합니다.

새로운 타일 선택 매핑과 동일한 마스크 버전에서 같은 `(num_64, 순서 있는 supp 목록)`은 같은 좌표와 소비량을 만듭니다. 과거 직접 32+32비트 매핑의 동일 난수열과 좌표·보완 소비가 같다고 주장하지 않습니다. 첫 후보가 거부되면 `num_64`만으로 최종 국내 좌표가 결정되지 않습니다. 기본 값 자체와 다른 필드의 계산 순서는 유지되지만, 여러 레코드가 보완 목록을 공유할 때에는 국내 좌표가 추가로 소비한 만큼 후속 레코드의 입력 순번이 이동합니다. 기존 TXT에 이미 기록된 좌표의 추출·주소 조회는 그대로 사용할 수 있습니다.

### 저장 형식·로딩·오류 처리

v4는 원본 링의 연속 에지와 수평 교차 정보를 0.03125° 타일에 저장합니다. 원본 정점을 반올림하거나 클리핑하지 않습니다. 41,241개 타일 중 `OUTSIDE` 29,229개는 즉시 거부하고 `INSIDE` 9,435개는 즉시 수락하며, `MIXED` 2,577개에서 원본 에지를 검사합니다. 타일 이음새는 동쪽·북쪽 셀이 소유하고 전체 최댓값은 마지막 셀에 포함합니다. 모든 타일 분류와 전체 마스크 동치는 독립 GEOS로 확인했습니다.

원래 경계 바이너리(루트+96개 조각) 합계는 **50,276,630 bytes**로, 이전 v3의 103,444,465 bytes보다 **51.40% 감소**했습니다. 이 합계에는 499,628-byte 루트 인덱스와 96개 압축 조각이 포함되며, 압축 페이지는 25,348개입니다. 2배수 선택용 32,768-byte 비트맵 `tile-select-v5.bin`은 이 합계와 별도이며, 함께 배포해야 합니다. 경계 자체의 97개 바이너리·정점·구멍·국경선은 변경하지 않았습니다. 생성기는 페이지 순서를 유지하며 조각당 512 KiB 이하로 묶습니다. 런타임 형식 검사의 조각 상한도 512 KiB, 해제 페이지 상한은 32 KiB입니다. 전체 데이터와 파일별 SHA-256은 [manifest](data/korea-boundary-v4/manifest.json), 원본 보정 근거는 [보정 검증자료](data/korea-boundary-v4/boundary-validation.json), 재구성 동치는 [기하 검증자료](data/korea-boundary-v4/geometry-validation.json)에 기록합니다.

후속 최적화에서는 기존 조각 배치를 유지하며 Rust의 압축 해제·해시 검증과 웹의 짧은 허프먼 코드 조회를 개선했습니다. 웹 변경은 고정 Chromium 코퍼스의 5회 비교에서 중앙값을 약 4.65% 줄였으며, 코드 2줄·123바이트 증가와 캐시·요청 수 유지를 함께 평가해 채택했습니다. 64 KiB 조각 재배치 후보는 통제한 HTTP 응답 지연 조건에서 요청 증가에 따른 회귀가 확인되어 채택하지 않았습니다. 후보별 측정과 선택 근거는 [v4 성능 보고서](docs/korea-v4-performance-accepted-js-20261029.md)에 기록합니다.

추가 좌표 생성 최적화는 Rust의 경계 데이터 SHA-256 검증에서, 지원하는 x86_64 CPU의 전용 명령을 런타임에 선택합니다. 다른 CPU는 기존 계산을 사용하며 데이터 형식, 해시 결과, 좌표 비트와 보완 난수 소비를 유지합니다. SHA 지원 Linux x86_64에서 직전 채택본 대비 고정 입력 1만 건은 5회 비교 중앙값 18.43%, 실제 병렬 CLI 1만 건은 25회 비교 중앙값 17.55% 빨라졌습니다. 첫 좌표 지연, 메모리, 공식 배포 패키지와 남은 네이티브 환경 검증 제약은 [추가 좌표 생성 성능 보고서](docs/korea-v4-coordinate-performance-20261029.md)에 기록합니다.

Rust 실행 파일은 전체 경계를 내장하므로 실행 중 경계 파일이나 네트워크가 필요하지 않습니다. 대량 생성은 기존 작업자별 캐시 수명을 유지합니다. 페이지 payload와 살아 있는 캐시 항목의 회계상 한도는 작업자당 1 MiB·4,096페이지이며, 단발 변환도 해당 변환 동안만 임시 캐시를 사용합니다. 압축 해제에는 9비트 조회표를 사용하며 고정 허프먼 트리를 재사용합니다. SHA-256은 64-word 스케줄로 검증합니다. 이 캐시 수치는 실행 파일 매핑·인덱스·할당기·여유 capacity·허프먼 표·해시 작업 배열·32 KiB 해제 스택을 포함한 전체 RSS 한도가 아닙니다.

웹은 압축 조각 최대 8개·4 MiB와 해제 페이지 최대 4,096개·4 MiB를 보존합니다. 진행 중 조각 로딩은 최대 8개이며, 완료 전에는 요청당 런타임 상한인 512 KiB를 예약하고 완료 후 실제 크기로 정산합니다. 해제 페이지도 진행 중 최대 크기를 예약해 같은 payload 예산을 적용합니다. 루트 인덱스, JavaScript 객체, 일시적인 복사 버퍼와 브라우저 자체 HTTP 캐시는 이 예산과 별도입니다. 모듈과 인덱스를 수동 입력 탭에서 준비하고 입력값의 첫 타일을 미리 읽지만, 사전 로딩은 보완 난수를 소비하거나 결과를 확정하지 않습니다. 기존 TXT 분석은 `revgeo.html` 하나로 가능하고 경계 모듈·데이터를 내려받지 않습니다.

웹 수동 변환에는 `korea_boundary.js?v=5`과 `data/korea-boundary-v4/`를 같은 구조로 제공하는 HTTPS 또는 localhost 보안 컨텍스트가 필요합니다. 웹 조회 경로 갱신에 맞춰 모듈 캐시 식별자를 올렸으며, 경계 바이너리의 형식과 데이터는 v4를 유지합니다. 루트 SHA-256을 코드에 고정하고 각 조각의 SHA-256·버전·길이·범위·zlib Adler-32를 검사합니다. 요청 URL에도 기대 해시를 넣어 데이터 갱신을 구분합니다. 누락·손상·버전 혼합을 바다로 간주하지 않으며, 오류 후 대체 좌표를 만들지 않습니다. 이후 데이터 갱신 시 모듈의 캐시 식별자와 고정 루트 해시도 함께 갱신해야 합니다.

### 재현과 검증

원본 시도 SHP 세트와 KEI MDL·DMZ ZIP으로 동일한 보정 SHP를 먼저 재현해야 합니다. 기대 SHP SHA-256은 `5060f88241e2d80b87f052b4b83296ef59cd7f4ee066a9330bc2ea580bc55428`입니다. 원본 보정 도구의 정책은 변경하지 않았습니다.

```bash
python -m pip install -r tools/requirements-korea.txt
python tools/correct_korea_boundary.py --sgis-dir SGIS --kei-mdl mdl.zip --kei-dmz dmz.zip --out-dir corrected
python tools/build_korea_boundary.py corrected/land_mask_5179.shp \
  --output rebuilt/korea-boundary-v4 --tile-scale 32 \
  --rust-module rebuilt/data.rs \
  --boundary-validation data/korea-boundary-v4/boundary-validation.json
```

생성기의 출력 디렉터리는 비어 있어야 합니다. 위 명령은 재생성 결과를 `rebuilt/`에 저장하고 기존 15개 지리 프로브를 명시적으로 대조합니다.

생성기는 전체 원본 좌표 비트, 폴리곤별 GEOS `equals`·빈 대칭차, 전체 마스크 유효성, 모든 타일 분류, 조각 해시와 압축 스트림을 확인합니다. 무손실 검증에 성공한 후 v3 삼각형 자산과 런타임 경로를 제거했습니다. 현재 좌표 생성 최적화와 최신 측정값·검증 제약은 [추가 좌표 생성 성능 보고서](docs/korea-v4-coordinate-performance-20261029.md)에 기록합니다. [직전 JavaScript 채택 보고서](docs/korea-v4-performance-accepted-js-20261029.md)는 quick9 채택과 당시 성능·검증을 보존합니다. [이전 성능 검토 보고서](docs/korea-v4-performance-20261029.md)는 웹 후보를 재평가하기 전의 판단과 측정을 그대로 보존합니다. [v4 도입 검증 보고서](docs/korea-v4-validation-20261029.md)는 최초 v4의 독립 지리·수학 검사와 당시 측정·진단을 그대로 보존한 체크포인트이며, [2026-10-28 보고서](docs/uniform-performance-20261028.md)는 그 이전 버전의 역사적 측정입니다. 현재 바이너리 형식과 수치 연산 규약은 [v4 형식 문서](docs/korea-v4-format.md)를 따릅니다.

## GitHub Actions

- **CI**: `main` 브랜치와 태그에서 Windows, Linux, Intel Mac, Apple Silicon Mac용 release Artifact를 제공합니다.
- **Run SRG Manually**: 데이터 생성, 사다리타기, 범위형 난수 생성과 서버 시간 관찰을 선택해 실행합니다. 실행 결과는 Actions 로그에서 확인하고, 생성 데이터는 `random_data.txt` Artifact로 내려받을 수 있습니다.
- **pages build and deployment**: `revgeo.html`을 GitHub Pages 웹페이지로 빌드하고 배포합니다.

새 타일 선택 규약과 재현 검사는 [2배수 타일 샘플링](docs/korea-v5-tile-sampling.md)에 설명합니다.
